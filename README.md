# DeepEncode — AI Cognitive Schema Architect

DeepEncode is a local-first learning app that turns passive study material (notes, PDFs, images, YouTube lectures) into **active cognitive encoding workouts** grounded in learning science — the generation effect, dual coding, method of loci, chunking, interleaving, metacognition, and more.

Instead of re-reading, you reconstruct: every AI-generated stage opens with a physical paradox to resolve, an extreme thought experiment to run, and a mechanistic crux to write in your own words. Nothing is graded. The examiner is a lab partner: it tells you which causal links landed, writes the one missing sentence for you, and asks a single question that pushes your mechanism to its edge. The flashcard is never the assignment, only the fossil record of an aha that already happened.

## Features

- **Interactive intuition laboratories** — six fixed, validated mathematical engines turn suitable source material into prediction-gated toy models: ratio/scaling, saturation/Hill curves, ideal two-state equilibrium, weighted state cycles, critical activation/collapse/sign-change thresholds, and coupled two-species phase planes (Lotka–Volterra orbits with a conserved quantity, nullclines and a draggable operating point). Sliders, brass/cyan SVG instruments, counter-model comparisons, restrained audio and source/assumption disclosure keep the science inspectable. A **Devil's Advocate duel** lets a fictional student voice a confident fallacy that can only be refuted by reconfiguring the same lab — an engine-verified verdict, exported as its own trap card. Revealed boundary rules persist and export as schema-scoped interference-trap cards to Anki/RemNote. Six explicit no-key teaching examples are on the launchpad. See [the detailed architecture and limitations](docs/interactive-labs.md).

- **Interactive pathway builder** — the energy-payoff phase of glycolysis as a causal chain: drop the enzyme and cofactor each step requires, with real decoys (an investment-phase enzyme, a product cofactor) in the palette. Grading is declared chemistry, never a heuristic — a wrong piece is named with what it actually does, flow is causal and sequential so yields unlock in order, and the product only forms when every step is catalytically complete. Every step quotes the sentence it was derived from, and the validator refuses a quote that is not literally in the source.

- **Course-level prerequisite skill tree** — every prerequisite audit you have run is persisted with its topic and resolved across the whole library: green for fully encoded courses, amber for work in flight, and locked leaves for foundations nothing in the library covers yet (with the audit's own 30-second primer attached). Coverage is decided locally and conservatively — a one-word concept can never claim a course — so the tree cannot pad itself with false links.

- **Encoding sessions** — text, file (PDF/image), or YouTube input; `conceptual` and `memorization` modes with smart mnemonic auto-detection
- **Teach Me (deep mode)** — Brilliant-style interactive lessons, authored at whatever depth you ask for. Three passes per idea: `concept` (intuit it) → `deepDive` (the causal **why**, the limits, the failure modes) → `misconception` (the plausible wrong belief, killed), with every teaching segment carrying its own `why` block. The lesson then makes you *produce*: `checkpoint` → `guidedProblem` (one move at a time) → `youTry` → `selfExplain` (Feynman it back, against a reference answer) → `transfer` (same mechanism, unfamiliar surface) → `recap`. You pick the level of detail (`standard` / `deep` / `exhaustive`, up to 40 segments), the lessons carry objectives and a glossary, and only one idea lives on a card at a time. **Encoding is not part of the lesson**: it ends with `[ START ENCODING ]` or `[ SAVE IT FOR LATER ]`. **A lesson request that fails still teaches** (defect 43): the deterministic lesson builder takes over instead of returning you to the pre-roll with an error, built from the same topic and — for a stage lesson — that stage's own mechanism, prompt and confusable lookalike. It is labelled rather than disguised, `data-origin` telling a lost connection from a service that answered with an error (that error stays on screen when there is one), `[ TRY THE MODEL AGAIN ]` hands you straight back to the model, and checkpoints, XP, the encode prompts and the save-for-later exit all work on it unchanged
- **Encoding deferred to the end** — the lesson is self-contained teaching, so nothing inside it tells you to encode. When it finishes, the exit panel shows the `encodingSeeds` it built (stage-sized prompts with reference exemplars) and you choose: **start encoding** hands the finished lesson to the workbench (a notes lesson runs the encode pipeline, a stage lesson drops you back into the stage you are in with the mechanism field focused), or **save it for later** parks the whole lesson — content, progress, XP, seeds — in the saved-lesson library. The pre-roll then offers `[ RESUME ]`, and closing mid-lesson parks your place instead of losing it, so "later" can genuinely mean tomorrow
- **15 visual stage templates** — Memory Palace, First Principles, Analogy Matrix, Contrast Grid, Concept Hierarchy, State Transition, Mnemonic Peg, Broken-Model Debug, and more (`components/stage-templates/` + declarative registry in `lib/templates/`)
- **Cognitive gears** — encoding used to demand the same full workout every day, which is exactly why a Thursday night after labs felt like homework. The launchpad asks how much energy you actually have: **Express Forge** (low, ~60s — the encoder extracts the mechanism and blanks 2-3 pivotal words, each answerable in one or three words), **Interactive Puzzles** (medium — ordering, flaw-hunting, discrimination, zero essay), or **Deep Crucible** (high — full Feynman, spoken aloud, adversarial viva). The gear also sets how hard the examiner probes, so an Express session never opens with a ruthless viva. Science preserved at every gear: Slamecka & Graf's generation effect shows that generating a single missing word buys almost the same memory boost as writing the whole paragraph. Gear 1 is not a lesser workout, it is the same workout with the essay removed
- **Mr M mode** — one switch that re-shapes every stage for one particular learner: intensely deductive, first-principles, and unable to hold a procedure that has no physical mechanism attached to it. Seven surfaces, registered as **overlays on top of whichever template a stage already uses** (`lib/mr-m/registry.ts`, the same declarative shape as the template registry) rather than as replacement templates, so all sixteen templates still draw. **Axiom first** states the governing law and the coordinate origin (`ΔH°` is sea level: products − reactants) *above* the answer fields, so the mechanism exists before the procedure — and it pre-empts the adversarial question with the rule's own sharpest counterexample. **Ontology cards** give every symbol a physical identity and say what it is *not* (`m` is the water in the calorimeter, not the solid; `q` is heat *into* the system), so nothing in the formula is numerology. **A linear state-machine rail** decomposes a four-rule problem into step 1 → 2 → 3, each step carrying the ONE rule it consumes and the value it hands forward, so working memory never holds two. **What-if perturbation sliders** re-evaluate the stage's invariant client-side (`lib/mr-m/perturbation.ts`, no model call, never throws) with `base` / `×2` / `÷2` / `→ limit` presets per variable, because the proportional reasoning is the strength being spent. **A trap-aware autopsy** leads a failed check with the *structural* failure mode and the arithmetic that proves it (styrene `C₂H` → `0.0336 ÷ 0.0168 = 2.00`) — the label and the ratio are computed in `lib/mr-m/diagnostics.ts`, so a displayed number can never be hallucinated, and only the narrative (why it is structural, the corrected construction) is asked of the model. **A Socratic two-way check** sits beside the examiner's counter-probe: confirm or challenge in one committed line before the spar advances. And a **paradox ledger** holds an unresolved contradiction (localStorage, newest first, with its age) until the sentence that closes it exists — it warns loudly and says you may carry on regardless, because a hard gate would be the same arbitrary authority the mode exists to remove. A stack this deep would be in the way if it were permanent, so the preparation surfaces fold to one named line in a click (nothing switches off, and the fold starts expanded); the decomposition reports `2 of 3 held` and resets in one control, because a mis-tick used to have to be undone one box at a time; and the sliders carry a single reset back to the stage's own numbers. The autopsy says which half is which — the ratio is *computed from your numbers, not written by the model* — because a learner who has been burned by a confidently wrong model needs to know which figure they can check for themselves. All seven panels are memoised and take only props that are stable while you type, so a keystroke in an answer field no longer redraws thirty slider presets three columns away. Default **on**; flip it from the masthead `Mr M` pill or the Settings switch, and the open-paradox count appears on the analytics dashboard. With the switch **off** the encode and evaluate prompts are byte-for-byte unchanged and every surface is additive — the stage renders exactly as it did before. And the mode's records are durable now: a trap the autopsy named can be saved as a real interference-trap card (the learner declares the confidence they held — the one input no code can know — and the card ships at the front of the Anki deck), a paradox closed with a resolution sentence ships into the deck as a `Paradox` card the Wozniak ceiling may not split, and every ontology card travels with the deck so the letter identities survive the session.
- **Paradox-first stages** — no stage opens with a definition request. Each one leads with the physical contradiction it exists to resolve (*"active ion pumps cannot build more than ~200 mOsm of gradient in one step, yet the loop of Henle reaches 1,200 mOsm. How?"*), followed by a **Gedankenexperiment** to run before formalising anything (*"You are an enzyme. The pH drops from 7.4 to 2.0. What physically happens to you, step by step?"*). Definitions are homework; paradoxes are irresistible, and the same mechanism has to be reasoned out either way
- **The Socratic clue ladder (how you get unstuck without being told)** — every stage's generation challenge used to carry exactly one hint behind a toggle, which is a coin flip: it either gives the answer away or leaves you stuck, and which one it is depends on how stuck you already were. The challenge now carries **2-3 ordered rungs** (weakest first) and hands them over one at a time — a nudge, then a narrower hint, then the strongest scaffold the stage can offer (`Socratic Clue 2 of 3`). Every template that carries a challenge shares the one control (`components/stage-templates/ClueLadder.tsx` + `lib/clue-ladder.ts`), so the affordance and the staging are identical wherever you meet it, and each template's own button wording is preserved. A deck payload written before the ladder existed reads as a one-rung ladder rather than losing its hint, a rung the model repeats is deduped rather than shown twice, and rungs beyond the third are not staged at all. There is deliberately **no answer key**: the ladder stops at the strongest scaffold and says so, because a revealed answer ends the recall attempt and the attempt is what encodes. The encode contract asks for rungs that make the answer *derivable* and forbids the cheap tricks by name (no spelling counts, no "starts with M", no restatement of the target); a rung a stage cannot supply is dropped rather than staged empty, and a stage with no hint renders no control at all
- **A lab partner, not a grader** — the examiner returns no score, no grade, no XP and no band. It returns whether the mechanism landed, the causal links that did (quoting you), the ONE sentence that completes it (written for you, never *"add more detail"*), and a single counter-probe that pushes your mechanism to its edge (*"what happens if vasa recta flow surges 500%?"*). Answer it in two words and you are done
- **Crystallization** — the cards are the exhaust of the engine, not the engine. Nothing is asked of the flashcard until the mechanism has landed; then the cards drop out on their own, read straight off the same fields the exporter ships, and `Cmd/Ctrl+Enter` injects them into Anki. Every word on them is a word you just reasoned through, which is why none of them become leeches three weeks later
- **Flashcards Only (the forge)** — sometimes you do not want a workout at all: it is Thursday, the exam is Friday, and you have four PDFs, two lectures and a topic you half-remember. The launchpad's `[ FLASHCARDS ONLY ]` button takes up to **12 sources at once** — pasted notes, several PDFs / slide photos, and a list of YouTube links — and cuts them straight into cards: **facts** (atomic clozes), **mechanisms** (4-quadrant concept cards carrying the lookalike trap), **drills** (rapid-fire Q/A) and **worked examples**; each section can be switched off. The forge reports rather than hides: one line per source (`[ OK ] Lecture 4 slides — 4 cards` / `[ ! ] youtube:renal — this video HAS captions (6 tracks) but this server could not read any of them, and …`), a duplicate count for what the merge dropped, and a source that yields nothing is named with its reason instead of being invented around. Then you choose where the deck lands — **Anki**, **RemNote**, or **both** (`BOTH` opens Anki and queues RemNote behind it rather than stacking two modals). A forged deck and an encoded deck are the *same artifact*: both are cut to the shared card contract (`lib/services/segregation.ts`), merged/deduplicated by `lib/services/forge.ts`, and handed to the identical Wozniak pass, discrimination gate, FSRS audit and export funnel. The only difference is that nothing here becomes a stage, a paradox, an XP bar or an examiner
- **Reshaping a deck in place (`[ + GENERATE MORE FLASHCARDS ]` / `[ CONDENSE SOME FLASHCARDS ]`)** — 30 cards when you expected 60 is a failed deck, and 90 cards that say the same thing four times is a failed deck too, so the forge does not make you re-run it from scratch to fix either. **Generate more** re-reads the SAME sources with the deck's own card fronts handed to the model as a do-not-repeat list, and every card that comes back is deduped against the deck (`lib/services/forge.ts`) — it can only ever append, never quietly re-ship what you already have (`+2 more cards (1 repeat dropped) — the deck now holds 7`). A source's transcript is resolved once and reused, so a lecture recording is never transcribed — or paid for — twice. **Condense** runs one editor pass that folds overlapping cards into fewer, denser ones, keeps every conflict card intact, and refuses to shrink a deck with no real overlap (`Condensed 7 → 3 cards`). Both passes re-run the deck-memory diff, so what exports is the reshaped deck with honest "already in your deck" counts
- **The forge reports coverage, not a card count** — `24 cards` says nothing about whether the deck is *complete*, so the summary answers the question you actually asked: a per-section coverage report (facts / mechanisms / drills / worked examples, requested vs. delivered), a named list of the sections that came back **empty**, and the post-Wozniak count — the deck you will actually export, after the 1-idea rule, two-way cloze symmetry and the 20-word ceiling have run, with the cards the ceiling held back counted separately instead of quietly inflating the number. Each source is also checked against its own yield: a lecture that runs 4,000 words and returns 2 cards is flagged `Under-mined:` (words in → cards out, at ~250 words per card) rather than passed off as an ordinary result, because the failure there is the mapping, not the deck. And because twelve sources is a real spend, the footer estimates it before you press the button (`12 sources · ~14 model calls · up to 4 transcribed · cut 3 at a time`), with the estimate following the sources you actually left in. The gap is attributed too, not just reported: `0 cards for examples` becomes `no source produced examples (Lecture 4 slides, Problem set 4)`, which is a note about the reading rather than about the model — and the summary states the direction rule up front (`Fronts: 3 two-way · 11 one way only — 2 are labels or questions (Step 2, vs X)`), because a front that is a label can only ever be asked one way and that is something to fix in the source, not to discover in a review queue
- **Grow to a target, step back one reshape, retry one source** — the forge's repair loop is a loop, not a button. Set a target (`60 cards`), press `[ GROW TO TARGET ]`, and it keeps asking for more — count ticking live, `[ STOP ]` always in reach — until the target is reached, you stop it, or TWO consecutive batches come back with nothing new, at which point it says the sources are exhausted at that number instead of inventing cards to hit a goal. Each batch is aimed at the coverage gaps still open (asking again for "everything" mostly re-earns the facts it already gave), and each batch is handed the deck *as it stands now*, so the model is never asked to avoid cards that were added a moment ago. Any reshape — more, condense, a retry, one batch of the loop — pushes the deck it replaced, so `[ UNDO ]` restores it in one step (`Condensed 5 → 3 cards` … `Undone — the deck is back to 5 cards`). And when one source in a batch of twelve fails, `[ RETRY ]` on its own row re-forges *just* that source — same request, restricted to that one id, reusing transcripts already resolved — instead of re-running (and re-paying for) the eleven that worked
- **Sources are cut three at a time, and you watch them land** — twelve sources used to be twelve sequential model calls, which is most of why the forge felt frozen for a minute. They now run through a pool of three workers, and `/api/forge` streams each one back as NDJSON (`phase` → `sourceStart` → `source`) as it finishes, so the runner shows the transcript being read and then that source's own card count while the rest are still in flight. Behind that, the merge is near-duplicate aware: beyond exact-front dedupe, a trigram/Jaccard similarity ≥ 0.8 over card fronts — guarded by length, numbers and polarity, so `half-life is 4 h` is never collapsed into `6 h` and `raises` is never collapsed into `lowers` — reports what it dropped as `already in the deck (M near-duplicate)` rather than shipping two cards that teach the same thing
- **Videos with no captions get transcribed, not dropped** — a lecture is read from its own caption track first: manual English, then the auto-generated (ASR) track, then any track at all, with each format retried (`fmt=json3`/`srv3`/default) because YouTube happily answers an empty 200 to a request it dislikes. Reading the track list from the embedded player response (not just the page HTML) is what makes ASR-only videos work, and it is why the forge can now say the difference between *"this video has captions and this server could not read them"* and *"this video has none"* — the old failure message blamed the video. **Only when there is genuinely nothing to read** does the forge transcribe the audio server-side and cut cards from the transcript. Uploaded recordings (m4a / mp3 / wav / opus / mp4) take the same transcription path, which is the half that always works, and a deck cut from a transcript says so in its source log. Transcription needs one endpoint: set `TRANSCRIBE_API_KEY` (any OpenAI-compatible `/audio/transcriptions` service; `TRANSCRIBE_API_URL` and `TRANSCRIBE_MODEL` override the defaults). Without a key nothing breaks — the source is reported as "no captions, and transcription is not configured"
- **Cross-source contradiction cards** — four PDFs and two lectures rarely agree, and a merge that quietly keeps whichever claim arrived first teaches a coin flip: *the slides say the half-life is 4 h, the lecture says 6 h, and the deck asserts 4 h*. So the forge compares the surviving claims of every source pair, offline and conservatively — same subject with a different quantity is a `numeric` conflict, and the same sentence with an antonym or a negation flipped (`lowers`/`raises`, `does not reverse`/`reverses`) is a `polarity` conflict. Each conflict replaces BOTH conflicting cards with one card that names both claims and both sources, tags it `Contradiction`, and leads the deck; the panel above the source log quotes the disagreement so you can settle it in your notes. Conflict cards are exempt from the Wozniak ceiling for the same reason trap cards are: the card *is* a discrimination pair, and chunking it would delete the distinction. Authorship is respected too — a source contradicting itself is not flagged as an exam trap
- **Deck memory ("4 new · 12 already in your deck")** — the forge's real use is repetition, and handing back the same deck every Monday makes it useless. Every deck that actually leaves the app (forge handoff, `.apkg`/`.txt` download, AnkiConnect push, webhook dispatch, RemNote push) records a fingerprint per card front under its topic — normalized text only, no backs, no answers, no source material. The next forge over that topic diffs against it and says `0 new · 5 already in your deck`, defaulting to **shipping only the new cards** (one toggle ships the whole deck instead), and `[ FORGET THIS TOPIC'S MEMORY ]` clears it. It is advisory: an edited front counts as new, and it never blocks or deletes anything. The fingerprints are the fronts the *exporter* writes, so a card forged here and the same card read back out of Anki are recognized as the same card. The memory is no longer trapped on one machine either: with an account signed in it mirrors to Firestore (`users/{uid}/memory/decks`) on every handoff and merges what the account knows against what this browser knows when the forge opens — per topic, key union, newest surface wins, export counts maxed — so the Sunday deck forged on the desktop recognizes what the laptop already shipped. Signing out degrades to the local store, and a sync that fails says so rather than blocking the forge. It also remembers **which sources** built a deck (a fingerprint per source: its URL, its file name, or the opening words of its pasted notes), which is what makes the ingest memory-aware rather than just the export: add a lecture you have already cut and the setup says so *before* the model call is spent — `2 of 4 sources already cut into a deck (14 cards so far)` with a per-row `[ FORGED × 12 ]` badge and a `[ SKIP ]` toggle that takes them out of the run (`2 skipped · ~2 model calls`). Nothing is dropped silently: the skip is offered, counted, visible in the pre-flight, and one click back
- **Anki-authoritative deck memory** — an app that only remembers what it pushed is wrong twice: a deck built before this feature (or imported by hand from an `.apkg`) is invisible, and a card edited in Anki still counts as new. So the memory asks the real collection first — `deckNames` → `findNotes` → `notesInfo` over the `DeepEncode::{Topic}` decks (`lib/anki-memory.ts`) — fingerprints those fronts, and merges them in without counting an export. A hand-built deck now reads as `4 new · 1 already in your deck`, the panel shows its provenance (`Checked your Anki deck: 42 notes in 2 decks.`), and `[ CHECK ANKI ]` re-reads it on demand. Only `DeepEncode` decks are read (the rest of the collection is never scanned), matching is segment-wise so both spellings this app has written (`Renal Physiology` / `Renal_Physiology`) and their subdecks are found, and the whole thing is advisory: with Anki closed the local diff stands and the panel says *"AnkiConnect is unreachable, so this is this app's own memory only"* instead of pretending it checked
- **Forge recipes** — the weekly ingest is the same four sources, the same sections and the same destination, so the setup itself is worth saving. A recipe stores which sources (text and video whole, files by name), which card sections, and which export target; `[ RUN ]` loads it and forges immediately, `[ LOAD ]` just fills the form, and a recipe that used PDFs says which files to re-attach instead of quietly forgetting them. Recipes live in localStorage, survive a reload, and are capped at twelve
- **Science stack** — prerequisites audit, pre-testing (productive failure), per-stage confidence + reflection, blurt canvas (free recall), roast-my-notes professor audit, end-of-session readout, analytics dashboard
- **Guided Path** — auto chunking of huge inputs into sequential modules with Feynman checkpoints
- **Streaming generation** — an encode is one long JSON response, and holding every pixel until its closing brace is a large part of why a 40-second generation feels dead. The launchpad now posts to `/api/encode/stream`, which runs a cheap outline pass first and streams it as newline-delimited JSON — the topic title, then one `outline` event per stage the moment each stage closes, then `phase` updates — with the full schema arriving behind them. `lib/stream-schema.ts` reads that JSON incrementally (depth- and string-aware, so a chunk that splits an escape sequence, or a key from its colon, resumes instead of guessing) and `lib/encode-stream.ts` paints it into the loading view's stage lozenges and a progress bar that actually moves. The outline is advisory: if it fails, the schema still generates, and the plain `/api/encode` route remains the fallback whenever a stream cannot be read
- **YouTube chapter mode** — one mini-workout per chapter, tied to real video timestamps
- **Knowledge map** — graph view of concepts and topics you've encoded, with connections and gaps
- **Exports** — Anki `.apkg`, RemNote hierarchy (including RemNote power syntax), SM-2 webhooks, stateless share links (LZ-compressed URLs, zero DB required). The share payload rides in the URL **fragment** (`#share=`), so it never reaches the server's request line — a query-string link of the same schema is refused with a **431** before any route runs. Past 2 KB the sheet says the link is longer than a chat message and offers the deck *without the author's written answers*; past 8 KB it stops offering a link at all and hands over a schema file the recipient restores through Analytics → `[ RESTORE BACKUP ]` (older `?share=` links are still read). RemNote decks keep BOTH card shapes the source produces: a `{{deletion}}` fact ships as a real RemNote **cloze** card and a short prompt ships as a descriptor card, so no deletion is dropped in favour of a Q/A card just because the AI wrote both
- **RemNote export: one document per card section, and only the cards that deserve a reverse** — a four-section deck pasted as one blob became one unreadable page, so the deck now ships as **one document per card section** — `Renal Physiology — Declarative Facts`, `… — Mechanisms`, `… — Practice Drills`, `… — Worked Examples` — each with its own one-click copy, its own named page and its own count (`12 cards · 1 two-way · 11 forward-only · page Renal_Physiology_Mechanisms`); `Copy all as one document` is still there for when you do want the whole thing. Card *direction* is now a decision per line rather than one default for everything: `::` makes a RemNote **two-way** card and `>>` makes a **forward-only** one, so a reverse card only exists where the front is a *name* that could be recalled from its definition — the mechanism headline, a research prerequisite. Every labelled prompt, numbered step, contrast row and question front ships `>>`, because RemNote's reverse of those asks *"given `Plug values`, name the label"*, which can never be answered and so never leaves the review queue. A `{{deletion}}` carries no delimiter at all: RemNote already reads it as a forward-only cloze, and `::` on top of it is what asked for the label back. A `[ Two-way cards ]` toggle flattens the whole deck to forward-only in one click, and `Push to API` follows the same shape — one document per section, in order, stopping at the first refusal with `Pushed 1 of 4 documents, then RemNote refused …` instead of reporting a half-pushed deck as a success. The push goes through this app's own `/api/remnote` route (RemNote's backend API authenticates with `apiKey`/`userId` headers and sends no CORS headers, so a browser can never call it directly), and the copy buttons always work regardless. Every RemNote copy path — the export sheet, the completed-session `Copy for RemNote` button and the history drawer — now goes through this one renderer, instead of three inline builders that each put `::` on every line. Underneath that, four things decide how much of a review queue the deck actually costs: **(1) explanations ride on the card as `#[[Extra Card Detail]]`** (RemNote's own powerup for a child bullet that shows on the card back and generates no card), so a concept is *one* card with its four quadrants attached instead of five cards each asking for a tag back — `[ Explanations as card detail ]` turns the old shape back on if you want it; **(2) a memory hook becomes a cloze hint** (`{{3 Na+ out}}{({3 out, 2 in})}`) on the deletion it explains, rather than a `Remember >>` card whose only content is the mnemonic and which is unanswerable on its own — and the hint is sanitised before it is glued in, because RemNote reads `{({…})}` up to its first inner `)`, so a hint like `near E_K (-90 mV)` used to be cut off mid-clause; **(3) content that is genuinely a list gets a list card** — a worked-example step chain is one `>>>` multi-line card and a keyword set is a `>>1.` list-answer card, because three steps of one procedure are one answer with three parts, not three unrelated cards; **(4) direction is overridable per card** — the smart rule decides it line by line, and the copy list shows every card as RemNote will ask it (with the ones that can only ever be asked one way named up front, `9 of 14 cards have a labelled or question front …`) with a small `::` / `>>` control to make an exception without flattening the whole deck; the counts update live. A deck forged over several sources also keeps its **provenance** (`sourceLabels` on the merged report, from the ids the merge already namespaces), so the same deck can be split **per source** (`Lecture 4 slides`, `Problem set 4`) instead of per section — `[ Split by: section / source ]` — and a coverage gap can name *whose* gap it is: `no source produced examples (Lecture 4 slides, Problem set 4) — ask again only if the material really contains it`. A deletion the source itself wrote is never buried in that detail: the quadrant stays a card, because Reveal-Only is exactly where a deliberate test would have gone to die. Three shapes exist because the alternative loses the knowledge they carry: an **ordered cascade** (a signalling cascade, a reaction cycle, an algorithm pass) ships as ONE `>>1.` sequence card with its steps nested in order, because five Q→A cards that each test one step still teach no chronology — and a cascade with only one step is rejected rather than shipped as a fragment; a **boundary tripwire** asks where a stated law *stops* holding ("Under what condition does Ohm's law stop holding?"), because hard exams probe the limit of validity far more often than the formula, and the failure shape may not be invented to fill the slot; and a fact's **clinical correlate** is its own card, not a longer back, since it answers a different question and folding it in would make one card carry two ideas. Both new shapes carry the `#[[Exam Trap]]` tag RemNote filters on, and a clinical correlate carries `#[[Clinical Correlate]]`, so "quiz me only on the traps tonight" is a review queue the deck can answer — a `High-Yield` tag was deliberately not added, because nothing in the data distinguishes it from everything, and a tag that matches the whole deck is not a filter
- **One-tap AnkiConnect push** — with the Anki desktop app open and the AnkiConnect add-on installed, `Cmd/Ctrl+Shift+A` at the forge creates the deck (`DeepEncode::{Topic}`), adds the stage's cards, and flashes a receipt (`[ANKI: +2 CARDS FORGED · 1 already in deck]`) without a download, an import dialog, or leaving the app. The export modal pushes the whole sanitized deck the same way. Duplicates are counted, never re-added; cards above the 20-word ceiling still ship tagged `WozniakOverflow` and the receipt says so
- **Procedural MCQ deck** — parametric AP-style multiple-choice archetypes authored from *your* notes, validated by a 50-trial numerical checker with automatic repair, exported as self-grading Anki cards that roll fresh numbers every review (100% offline in Anki)
- **Wozniak enforcement pass** — every card is sanitized before export: the 1-idea rule (a back joining two ideas with "and" becomes two cards), two-way cloze symmetry, and a 20-word information ceiling. The symmetry builds a *genuine* reverse — the card that cloze'd the effect now shows the effect and blanks the cause, so the pair tests two directions rather than the same one twice — and it declines when a sentence does not reverse, leaving the forward card alone instead of shipping a second copy that teaches nothing. (It used to cloze the verb, which is how `X causes {{c1::causes}}` reached `.apkg` files.) Cards the ceiling holds back are listed with reasons and stay out of the deck until chunked — or can be force-included, tagged `WozniakOverflow`
- **One card row per cloze deletion** — a native Anki export writes `ord = n-1` for every `{{cN::}}` in a note, and so does this one. Cloze numbering is normalized dense from `c1`, so a front carrying only `{{c2::…}}` (or `c1` then `c3`) can no longer ship a card row Anki cannot render, which used to lose the deletion silently
- **FSRS card audit** — flags too-long and ambiguous clozes before export, with one-click auto-split into atomic cards; weak-stage-only export toggle. Interference-trap cards and cross-source conflict cards are exempt from the Wozniak ceiling: a trap IS a discrimination pair (wrong intuition vs. truth) and a conflict card is one too (source A vs source B), so chunking either would destroy the distinction it exists to teach
- **Cognitive telemetry** — the completion report shows compression ratio (raw words → atomic cards, % noise stripped), information atomicity (average words per card back, count over the 15-word limit), and a jargon-deflation index, instead of XP
- **Taboo constraint engine** — the source's 5 highest-jargon terms are surfaced as banned chips in the workbench, flagged live as they leak into your wording, and enforced by the examiner prompt too
- **Delta feedback** — the examiner returns *what you nailed* plus the single *missing link*, with an inline "patch the gap" field that appends the one sentence straight into your mechanism answer
- **Blind prediction gate (Predict · Observe · Explain)** — before the schema is generated you commit to a confidence tier (*guessing / 50-50 / bet my life*) and then to one of four concrete predictions. Getting it wrong after betting your life is the **Hypercorrection Effect**: the reveal goes hazard-red, you must explain the physical flaw in one sentence, and the mistake is saved as an interference-trap card that leads the Anki deck
- **Priming warm-ups (pick the archetype)** — four pre-flight drills that make an equation or mechanism non-arbitrary before you touch it, each as long as the physics says: `Qualitative shape` opens a canvas and makes you **draw** the curve before the algebra, then commit to its limiting behaviour — the shape it had to have is named only after your hand has committed; `Source → sink` is a two-probe polarity check (where the density is concentrated, then which atom is stripped), after which the arrow can only point one way; `Unit puzzle` makes you assemble the units to discover whether it is v or v²; `Extremal check` is a three-probe sweep pushing each variable to 0 / ∞ in turn, which pins numerator vs denominator. `Auto` lets the examiner choose, picking a chip demands the drill. Every probe is one committed choice on a ten-second timescale, each step carries its own planted misconception, and the transferable rule lands in the stage answer with one click
- **The question-first inquisitor (a verdict on your own intuition)** — every other surface here asks you to produce something; this one interrogates what you already believe. You state a claim — *"breaking bonds releases energy"*, *"Taylor series are derivative matching"*, *"every smooth function equals its own Taylor series"* — and get back one of exactly three verdicts: **TRUE**, **FALSE**, or **TRUE, WITH A BOUNDARY**. No preamble, no "great question", no score: the first token is the verdict, the proof names the governing law and either derives the claim from it or shows where the derivation fails, and a `FALSE` is never allowed to arrive without the construction that does hold (`lib/inquisitor/`). The claim is quoted back above the verdict, so a misreading is visible in one glance instead of hidden inside an answer to a question you did not ask. What shapes the contract is the boundary: a model asked for a failure mode will invent one, so a tripwire verdict that arrives without a tripwire is **downgraded to TRUE** and the panel says why — believing your intuition has a known limit when nobody has found one is worse than believing it is simply true — and a verdict with no proof behind it is **refused outright** rather than rendered, because an unsupported claim about rigour is a coin flip that got lucky. A real boundary is a live contradiction for this learner, so it commits to the **same paradox ledger** the Mr M surfaces already hold contradictions in, and stays on screen until a sentence closes it; opening the cockpit pre-flights what that topic has already caught you on, trap cards included
- **Why-ladder ([ PROBE DEEPER ])** — interrogates your own wording one layer at a time until the chain bottoms out at something that cannot be reduced further: a conservation law, a finite resource, geometry, a dimensional necessity. Each layer answers the one question the layer above it dodged; the axiom is one click from becoming the card's anchor
- **Spot the inverted step** — adversarial discriminative repair for drained days: the examiner writes the mechanism as four causal steps and quietly falsifies exactly one (SNAREs zipping vs. disassembling, bond breaking releasing energy). You click the lie and write the one-sentence fix — recognition first, production second
- **10-second discrimination gate** — cards fail in review because a *neighbour* answers for them (SN1 for SN2, atropine for epinephrine), which self-graded review cannot see. Every export path in the deck modal (`.apkg`, `.txt`, the AnkiConnect push, the webhook dispatch, and the Procedural MCQ deck downloads) is gated by two blind vignettes — one the stage's concept, one its lookalike — each classified against a 10-second clock. Ten seconds *is* the mechanism: a discrimination you hold is immediate, while interference forces deliberation, so the hesitation is the evidence. A miss or a timeout flags the pair unstable, asks for the one operational rule that separates them, saves your wording as a trap card that leads the deck, and tags the export `DiscriminationUnstable`. If no blind pair can be built (or the stage has no boundary contrast) the gate says so and stands aside — a missing check is not a failed check. The in-forge `Cmd/Ctrl+Shift+A` push stays ungated on purpose: it captures a single stage mid-workout rather than handing off a deck
- **Causal Mad-Libs scaffold** — the stage's deduction is presented as ONE sentence with blanks instead of three unrelated boxes. The encoder writes the template (`[[1]]/[[2]]/[[3]]` with real connectives); when it does not, the frame is derived from the stage's own labels, so sentence mode is never unavailable. Tab walks the blanks, Enter submits from the last one, and the boundary contrast rides along as a read-only `UNLESS …` clause
- **Scrambled causal order (Parsons problems)** — `Order the chain` splits the mechanism into 4–6 true steps and shuffles them deterministically (same puzzle after a reload, seeded on the stage). Grading is positional: the drill names the first broken link and what must precede it, the examiner's pivot rule is captured for the card, and a correct chain locks onto the answer in one click. Zero typing
- **Interactive diagram completion** — a diagram you only read is recognition, not retrieval: first-principles chains, analogy matrices and state-transition cycles blank one of their own cells (the mechanism node, the missing target mapping, the rate-limiting trigger) and grade the link you produce. A wrong answer reveals the truth immediately; the link lands on the card either way
- **Chapter progress rail (video sessions)** — a 90-minute lecture is not one sitting. The rail shows which chapters are actually encoded, offers `Resume chapter N` at the first one still open, and clicking any chip jumps to that stage and seeks the embedded player to its timestamp
- **STEM input** — type ASCII and read notation: `r^{4}`, `_{m}`, `->`, `<=>`, `<=`, `\alpha`, `\sqrt{2gh}` render in a preview under the field, and `Formula input` switches the fields to monospace. The raw ASCII remains the single source of truth — that is what is graded and exported
- **Local-first storage** — IndexedDB with localStorage fallback and Firestore cloud sync (optional)
- **PWA** — installable, with an offline fallback generator when you have no network/key: a lost connection (or a connection that drops mid-request) is not reported as a failed generation, it builds the workout **on this device** from your own material — five deterministic template stages, same workbench, XP, export and history — and the masthead banner says which way the workout on screen was made. A server that *answered* with an error still alerts, because fabricating cards for a provider outage is not a fallback (`lib/services/offlineGenerator.ts`, defect 42). It is also installable in the literal sense now: the 192 and 512 icons the manifest declares are drawn and encoded in code and served at exactly those paths, and `public/sw.js` registers a network-first worker with a `fetch` handler, so Chromium's install criteria are met and a reload with the network gone paints the studio rather than the browser's error page (defect 45)
- **Multi-provider AI** — Gemini, OpenRouter, or any OpenAI-compatible endpoint (bring your own key)

## Getting started

```bash
bun install
bun run dev        # http://localhost:3000
```

**Optional — one-tap Anki push:** install the [AnkiConnect](https://ankiweb.net/shared/info/2055492159) add-on (code `2055492159`) in the Anki desktop app, keep Anki running, and add this app's origin to `webCorsOriginList` in *Tools ▸ Add-ons ▸ AnkiConnect ▸ Config* (AnkiConnect's default list only allows `http://localhost`, so add `http://localhost:3000` — or `"*"`). Without it, every export path still works through `.apkg` / `.txt` downloads. A page served over `https` cannot reach `http://127.0.0.1:8765` at all, so the push is a local-dev-server feature.

1. Open **Settings** in the app and paste an API key (Gemini recommended), *or* set `GEMINI_API_KEY` in `.env.local` (copy `.env.example`).
2. Paste notes, upload a file, or drop a YouTube URL and hit generate — or start from a launchpad preset.

## Design system

The illuminated theme (`tailwind.config.ts` + `app/globals.css`) treats the app as a dark hall lit from above: a few stone tablets, one gold accent, and typography that carries the structure instead of hairlines on every edge.

- **Surfaces** — `chassis` (the hall) / `deck` (tablets) / `inset` (recessed wells) / `edge` (warm hairline, used only where a real seam is needed)
- **Ink** — `bone` (vellum, high emphasis) / `slate-ink` (mid) / `solder` (muted)
- **Accents** — `amber` = gold leaf (primary action & emphasis) · `flux` = ultramarine (AI/Teach) · `signal` = verdigris (verified) · `hazard` = ember (errors). `gilt` is the gold used for seams, ticks and halos
- **Type** — Fraunces for headlines (`font-display`), IBM Plex Sans for prose & UI, IBM Plex Mono for data: inputs, badges, numbers, code
- **Depth** — one soft light from above the page, plus real ambient shadow and a single top hairline of light (`shadow-panel`/`shadow-raised`). No drop-shadow clutter, no glass, no neon
- **The hall** — the shell carries three fixed layers of atmosphere: the light line, a raked **shaft** of key light thrown down from the upper right, and a cold **bounce** filling the lower-left corner. The chassis already carries a blue-violet undertone, so the cold fill is what makes the gold read as metal instead of grey-on-black. A film grain on `::after` keeps it print-textured
- **The gold leaf** — the accent is real leaf on a dark ground, so it does not merely sit lit, it *catches*. A hairline of gilt **travels around each primary plate** on an animated `--leaf-angle` (registered via `@property` so the conic gradient interpolates instead of snapping), masked down to a 1px rim. Two entry points: `.leaf-edge` for a plate whose `::after` is free, `.leaf-frame` as an empty child for one that has already spent both pseudo-elements (the console draws its corner brackets on them). On the preset row the five offsets are staggered so one highlight chases across all five cards. In the workbench the leaf belongs to the **forge plate** — the stage you are actually working — while the source and examiner rails are static tablets (`ui-card` top light, no motion). The cyan instruments (toy labs, pathway builder) keep their scoped palette but share the shell's top light, tinted cool; when a toy model goes critical, its top light turns **hazard** with it
- **Editorial devices** — the hero opens with a manuscript **illuminated initial** (floated, never extracted from the sentence, so the paragraph still reads "Turn what you study"), an engraved **ruler** of fine and fifth-ticks, and the workflow as a ruled **ledger** whose dotted leader tracks the eye from index to label and whose edge tick lights on hover
- **Layout** — the shell is a masthead of type and a quiet nav cluster (no framed control strip). Panels are spaced tablets rather than stacked full-width bands: the launchpad is a writing surface with a depth/tuning rail on the right, the forge reads as a page of luminous blocks with a vertical gold spine on the paradox, and pre-flight audits and export targets are two separate tablets. Progress is a stage ticker of small lozenges, never a row of bars
- **Motion** — 150ms color transitions on interactive elements; a single `animate-dawn` bloom on the masthead; springs for modal enter/exit via `motion/react`; the gilt travelling around the plates is the only motion that never stops on its own, and `prefers-reduced-motion` parks it at its brightest angle so a still plate reads as gilded rather than switched off
- **Keyboard** — visible gold `:focus-visible` rings, backed by a faint halo so the focused control is findable in peripheral vision; generous radii (`rounded-lg`→`rounded-2xl`, pills for controls and chips) enforced through the theme scale

Shared primitives (Button, Badge, Card, Modal, Input, Textarea, Slider, Tooltip) are in `components/ui/`. Every sheet — primitive or hand-rolled — takes Escape, scroll-lock, focus-in/restore and the Tab trap from `hooks/useModalA11y`, so no modal re-invents its own keyboard contract. Every copy control in the app — drawer rows, the forge's
one-click RemNote handoff, the workbench, the toy-lab embed bullet, the RemNote and share sheets and the
completed session's format buttons — writes through `lib/clipboard.ts` and takes its confirmation from
`hooks/useClipboardCopy`: `copied` only for a write that actually landed, `failed` (with the shared message)
for one the browser refused, and a temporary reset either way. Each control carries `data-copy-status` for
that state. Every sheet mount in `app/page.tsx` also sits behind
`components/SheetErrorBoundary.tsx`, so a sheet that throws during render is the only thing replaced — the
session, the stage and the other sheets stay live. Every sheet also takes the hall's instrument language: `.leaf-edge.sheet-plate` (rim + machined corner brackets + rounded-2xl) is applied to the primitive and to all sixteen hand-rolled sheets alike — the treatment travels with the class, so a new sheet inherits it by carrying the same two tokens. Sheets unmount when closed, so the leaf costs nothing while no sheet is open; the hand-rolled ones keep `role="dialog"` on the overlay with the plate as its child.

  - A full 30-spec sweep is faster and steadier against a PRODUCTION build than against `next dev`, because every route is already compiled and page loads drop from ~10s to ~100ms: `bun run build`, then `bun run start -- -p 3000`, then `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3000 bun run test:e2e --workers=2`. `playwright.config.ts` reads `PLAYWRIGHT_BASE_URL` and, when it is set, does not launch its own server.
- **CI** — `.github/workflows/nextjs.yml` runs typecheck, lint, unit tests and the production build in one job, then the Playwright chromium suite (with the same `--workers=3` guard) in another.

## Firestore

Cloud sync (optional, per-user) uses Firestore. Deploy rules with:

```bash
firebase deploy --only firestore:rules
```

Cloud settings (`settingsBackup` on the user document) are applied on sign-in **only
when the account's copy is newer than the device's**: every write to the local record
stamps `savedAt` through `saveAISettings` (`lib/settings-sync.ts` holds the rules), the
reset and the backup restore stamp the moment the learner chose that content, and the
cloud restore keeps the account's stamp so a later edit made on another device still
wins. A record whose age cannot be read - no stamp, `0`, a string - is never applied.

Rules (`firestore.rules`) scope every read/write to the authenticated owner: `/users/{uid}/schemas/{id}` for encoded workouts, and `/users/{uid}/memory/{docId}` for the deck memory the forge mirrors there (front fingerprints only — no backs, no answers, no source material).
